# How we work

- **Good enough first, then iterate:** ship the thinnest slice that works end to end, get feedback, widen it. Polishing comes after something runs. "To require perfection is to invite paralysis" (David Bayles and Ted Orland, *Art & Fear*). "Most platform efforts fail not by starting too small, but by starting too broad": start from the Thinnest Viable Platform (Kaspar von Grünberg and Luca Galante, *Thinking in Platforms*, p. 29-30; [Thinking in platforms](../thinking-in-platforms.md)).
- **Open source first:** before building, look for an open source tool that already does it (see "Open source first, native first, build last" in [Rules](rules.md)).
- **Languages:** conversation with the owner in Portuguese (pt-BR); everything versioned (files, code, comments, commits, issues, PRs) in English.
- **Small context:** durable rules live in these guides and in the ADRs; `CLAUDE.md` only references them.
