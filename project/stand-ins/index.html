    Stand-ins¶

    Every workaround is a feature waiting for the platform (#113): what the project does by hand until the platform offers it (#269).

    Every pull request and issue says which stand-in it creates or retires; a feature that retires one carries the dogfood label.

    claude-peers (the owner's linux repository, #1360) reads Claude Code's own session registry (~/.claude/sessions/) and the process tree to tell a hook's headless helper session from a peer (#1340) ListAgents showing a session's parent, or the hook naming the session it starts (claude --name); then Triton's room (#618)
    An authentication Mandate's allow covers a whole namespace, builds, which every tenant shares, and a team writes its own Workload's repository; so a Token is asked only when the Workload's owner, and the Build's when it names one, are in the buildkit Nereid's BUILD_TOKEN_OWNERS (empty by default), and any other Build of a repository a Mandate covers stays Pending, TenantTokenNotSupported (#1070, spec 0009) #1331: a tenant's Build gets a clone token only for a repository its own Organization is allowed
